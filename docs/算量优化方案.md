# 算量优化方案 —— 面积 / 长度 / 体积三态统一

> 起草日期：2026-05-25
> 状态：方案定稿，待落地

---

## 0. 设计原则

> **几何只负责出量，策略只负责出规则。**
>
> **用户能看见的规则才是规则。** 任何会改变算量结果的判定，都必须有视觉锚点（图层、AttributeDictionary 标签、UI 红行确认）。几何启发只能产生「待确认建议」，不能默默改结果。

具体取舍：

- **量纲三态**：面（m²）、线（m）、体（m³），件（个）作为正交分支保留
- **策略分层**：每实例覆盖 > 图层规则 > 几何启发（仅产生建议） > 材质映射兜底
- **同材多算**：一个 SU 材质允许在不同 policy 下产出不同 `MaterialUsage`，分组键带 method 和 confidence
- **向后兼容**：现有 mapping/processes/前端不需要重写，只增量扩展

## 1. 数据模型升级

### 1.1 ScanItem 增加几何载体与策略字段

```ruby
ScanItem = Struct.new(
  :face_id,           # SU entityID（solid/linear_solid 时是 group/instance ID）
  :su_material,
  :kind,              # :face / :instance / :solid / :linear_solid    新增后两者
  :qty_area,          # 面积 m²
  :qty_length,        # 长度 m（face: bbox 长边；solid: bbox 最长边）
  :qty_volume,        # 体积 m³                                          新增
  :qty_count,         # 件数（instance 默认 1）
  :normal,            # 仅 face 有
  :width, :height,    # face bbox 短/长边
  :depth,             # solid bbox 第三维                                新增
  :layer_name,
  :component_path,
  :component_path_ids,
  :tags,              # AttributeDictionary 读出的覆盖标签                新增
  :resolved_method,   # Policy 决议结果 :area/:length/:volume/:count     新增
  :source,            # 决议来源 :attr/:layer/:heuristic/:mapping        新增
  :z_center
)
```

**关键变化**：原来的 `qty` 字段一物多用（面积/长度/件数），歧义大；现按量纲拆四个独立字段，由 Calculator 按 method 取用对应字段。

### 1.2 MaterialMapping 单位词表扩充

`config.json` 增加：

```json
{
  "area_units":   ["m²", "m2", "平", "块", "片"],
  "length_units": ["m", "mm", "cm", "dm", "km"],
  "volume_units": ["m³", "m3", "L", "立方"],
  "count_units":  ["个", "件", "套", "组", "台", "只"]
}
```

`MaterialMapping.record` 增加可选字段 `default_method`（`area | length | volume | count`），明确该材料默认量取方式。留空回退到 `unit` 词表推断。

### 1.3 MaterialUsage 增加置信度

```ruby
MaterialUsage
  ├ ...（原有字段）
  ├ confidence    # :explicit / :heuristic                  新增
  ├ source        # :attr / :layer / :heuristic / :mapping  新增
  └ items         # [ScanItem]
```

启发式判定与显式判定**不会被合并到同一条 usage**，分组键里包含 `confidence`，前端各显其色。

## 2. 扫描层（Scanner）

### 2.1 容器级整体量取（解决 6 面同材质场景）

ComponentInstance / Group 分支判定优先级：

```
1. component_mapping.aggregate?     → 产出 :instance ScanItem，return（已有）
2. policy.resolve_container == :length  → 产出 :linear_solid，return  新增
   - bbox 最长边作 qty_length
   - 不递归子面（关键：杜绝 6 面累加）
3. policy.resolve_container == :volume  → 产出 :solid，return         新增
   - entity.volume * 1.6387e-5 作 qty_volume
   - 不递归子面
4. opening_name?                    → 收集为洞口（已有）
5. 否则递归子面                       （已有）
```

`policy.resolve_container` 的判定来源：
- 容器自身的 `attribute_dictionary('su_takeoff')` 的 `method` 字段
- 容器所在 SU 图层命中 `layer_rules`

**容器没有命中 length/volume 规则时正常下钻**——这是与现状兼容的回退路径。

### 2.2 读取 AttributeDictionary 标签

Scanner 在打包 ScanItem 前读 `entity.attribute_dictionary('su_takeoff')`：

```ruby
tags = {}
if dict = entity.attribute_dictionary('su_takeoff')
  tags[:method]   = dict['method']    # 'area'/'length'/'volume'/'count'/'skip'
  tags[:material] = dict['material']  # 强制材料映射（可选）
end
```

attr dict 持久化在 SKP 文件里，跟模型走，删插件后仍在。**只对用户主动打的标签写 attr dict**，自动启发式判定结果不写——避免污染。

## 3. 决策层 —— TakeoffPolicy（新模块）

新增 `src/takeoff_policy.rb`。

### 3.1 优先级链（4 档）

```
1. AttributeDictionary（每实例覆盖）   显式 · 右键打标签 · 跟模型走
2. 图层规则                          显式 · SU 图层面板可见
3. 几何启发                          自动 · 弱信号 · 仅当面满足严格条件 · 产生待确认建议
4. 材质映射 unit                     兜底 · 由材料 unit 反推
```

**已删除**：组件名关键词规则（违反"显式优于隐式"，且无法约束用户命名）。

### 3.2 接口

```ruby
ResolveResult = Struct.new(:method, :source, keyword_init: true)

class TakeoffPolicy
  METHODS = %i[area length volume count skip].freeze

  def initialize(layer_rules:, heuristics_enabled:, mapping:)
    @layer_rules = layer_rules            # { '线条' => :length, '砌体' => :volume, ... }
    @heuristics  = heuristics_enabled
    @mapping     = mapping
  end

  # 面级判定
  def resolve(item)
    if item.tags && item.tags[:method]
      return ResolveResult.new(method: item.tags[:method].to_sym, source: :attr)
    end
    if m = @layer_rules[item.layer_name]
      return ResolveResult.new(method: m, source: :layer)
    end
    if @heuristics && linear_face?(item)
      return ResolveResult.new(method: :length, source: :heuristic)
    end
    if record = @mapping.get(item.su_material)
      return ResolveResult.new(method: method_from_unit(record.unit), source: :mapping)
    end
    ResolveResult.new(method: :skip, source: :default)
  end

  # 容器级判定（Scanner 调用）
  def resolve_container(entity, layer:)
    if dict = entity.attribute_dictionary('su_takeoff')
      m = dict['method']
      return m.to_sym if m && %w[length volume].include?(m)
    end
    @layer_rules[layer]   # 仅 :length / :volume 时触发整体量取
  end

  private

  # 严格的几何启发：必须是垂直面 + 横向窄长
  def linear_face?(item)
    return false unless item.kind == :face
    return false if item.normal.nil? || item.normal[2].abs > 0.5  # 排除水平面
    return false if item.width.nil? || item.width <= 0
    return false if item.width > 0.2                              # 短边阈值
    (item.height / item.width) > 15
  end
end
```

`PluginState` 持有一个 `takeoff_policy` 实例，Scanner 与 Calculator 共用同一份策略。

## 4. 计算层（Calculator）

### 4.1 主流程改造

```ruby
def compute(items, openings, process_overrides)
  items = dedup_thin_slabs(items)              # 现有：水平薄板
  items = dedup_vertical_slabs(items)          # 新增：竖直薄板（仅作用于 length 候选）
  opening_index = build_opening_index(openings)

  resolved = items.map { |it| [it, @policy.resolve(it)] }
              .reject { |_, r| r.method == :skip }

  # 分组键带 method 和 confidence —— 同材多算的关键
  groups = resolved.group_by do |it, r|
    confidence = (r.source == :heuristic) ? :heuristic : :explicit
    [extract_space(it), face_orientation(it.normal), it.su_material, r.method, confidence, r.source]
  end

  groups.flat_map do |(space, part, su_mat, method, confidence, source), pairs|
    items_in_group = pairs.map(&:first)
    case method
    when :area    then build_area_usage(space, part, su_mat, items_in_group, opening_index, confidence, source)
    when :length  then build_length_usage(space, part, su_mat, items_in_group, confidence, source)
    when :volume  then build_volume_usage(space, part, su_mat, items_in_group, confidence, source)
    when :count   then build_count_usage(space, part, su_mat, items_in_group, confidence, source)
    end
  end
end
```

### 4.2 三个 build_*_usage 方法

```ruby
def build_area_usage(...)
  gross = items.sum(&:qty_area)
  ded   = items.sum { |it| opening_index[it.face_id] || 0.0 }
  net   = items.sum { |it| [it.qty_area - (opening_index[it.face_id] || 0), 0].max }
  # 走现有面材逻辑
end

def build_length_usage(...)
  net = items.sum(&:qty_length)
  # 不扣洞口；linear_solid 与 face 都用 qty_length
end

def build_volume_usage(...)
  net = items.sum(&:qty_volume)
  # solid 不参与薄板去重；不存在洞口语义
end
```

### 4.3 后续计算已移除

当前版本只保留 `area / length / volume / count` 四类几何用量。后续材料展开、公式求值、采购换算等能力不再属于工作台职责；如未来恢复，应作为独立模块接在几何结果之后，而不是重新耦合进 `Calculator`。

### 4.4 去重链扩展

```ruby
def dedup_thin_slabs(items)        # 现有，水平薄板
def dedup_vertical_slabs(items)    # 新增，竖直薄板，仅作用于 length 候选
```

`dedup_vertical_slabs` 的约束：

- 仅对 `policy.resolve(it).method == :length` 的 face 跑
- 在 `(space, su_material)` 分组内
- 配对条件：normal 反向 + 面积差 ≤ 2% + 垂直距离 ≤ 50mm
- 命中即去掉一面（线材分支累加 height，留哪面结果一样）

`compute_geometry_only` 走同一份 policy，只输出几何用量，不做后续成本或做法计算。

## 5. 数据 & UI

### 5.1 配置文件

`data/config.json` 在原 unit 词表基础上：

```json
{
  "volume_units": ["m³", "L"],
  "layer_rules": {
    "线条": "length",
    "砌体": "volume",
    "保温": "volume"
  },
  "heuristics_enabled": true,
  "heuristic_thresholds": {
    "linear_min_aspect_ratio": 15,
    "linear_max_short_edge_m": 0.2,
    "vertical_dedup_max_gap_m": 0.05
  }
}
```

**已删除**：`component_rules`（组件名关键词）。

### 5.2 设置页

新增模块：

- **图层 → 计量方式**表（新增/编辑/删除行，下拉选 area/length/volume/count）
- 启发式开关 + 阈值（短边、长宽比、薄板配对距离）

**已删除**：组件名关键词输入框、扫描预览面板入口。

### 5.3 材料映射页

`unit` 字段下拉支持 `m²`、`m`、`m³`、`个` 等单位，并由 `TakeoffPolicy.classify_unit` 推导计量方式，让用户预览这条映射会被怎么算。

### 5.4 SU 右键菜单

选中 entity（face / Group / ComponentInstance）后右键：

- `按面积计算（强制）` → `set_attribute('su_takeoff', 'method', 'area')`
- `按长度计算（强制）` → `'method' => 'length'`
- `按体积计算（强制）` → `'method' => 'volume'`
- `不计入算量` → `'method' => 'skip'`
- `清除算量标签` → 删除 attr dict

### 5.5 待确认项

启发式判定的 usage（`confidence == :heuristic`）在组件树和明细中显示「待确认」状态，detail 展开区提供快速操作：

```
材料            部位   几何量      操作
────────────────────────────────────────────
爵士白         墙面   12.4 m²
待确认 爵士白条 墙面   8.0 m     [确认按长度] [改为面积] [跳过]
橡木复合地板    地面   20.0 m²
待确认 ?       墙面   16.2 m    [确认] [改判] [跳过]
```

操作行为：

- **确认**：把 method 写入这组所有 ScanItem 对应 entity 的 attr dict（每实例覆盖），下一轮扫描升级到 `:explicit`
- **改判**：弹出小菜单选 area/length/volume/skip
- **跳过**：写 `method=skip`，从结果中消失

实现走现有的 `send_workbench_state` 流：调 Ruby 端 `set_takeoff_method_batch(face_ids, method)` 写完 attr dict 后重跑 Calculator + 推前端。

### 5.6 「按组件」视图

树节点行同样支持 confidence 染红，末尾显示「待确认」徽标。

### 5.7 摘要条

```
共 28 项材料 · 已映射 25 · 未映射 3 · 🔴 待确认 4
```

「待确认」点击 → 跳到「按材料」视图并自动筛选 `confidence == :heuristic`。

## 6. 启发式开关的语义

设置页"启发式判定"开关现在控制的是：

- **开**：启发式生效，红行出现在结果中等待确认
- **关**：启发式不生效，相应面要么被材质 unit 兜底，要么被跳过；红行不出现

不再有"启发式自动改结果"的隐性行为。

## 10. 明确的取舍

- **不引入观察者增量更新**。SU `EntityObserver` 不可靠，「扫描按钮 + 全量重算」对住宅项目够用。
- **Solid 识别只看 manifold + volume > 0**，不强求"实体闭合无错面"；伪实体回退到面扫描，给警告但不阻断。
- **几何启发是弱信号**，永远排在显式规则后面，且只产生「红行待确认」，不直接出量。
- **不替换现有 mapping JSON 结构**，只新增可选字段（`default_method`），老映射继续工作。
- **散面建模 + 6 面同材质** 在启发式开 + 精细化判定 + 竖直薄板去重三件套全开时能拿到 8m 正确结果；任一缺失会得到错误值——文档中需明确告知用户首选 Group 建模。
- **没有组件名关键词规则**。命名约定无法约束用户、规则不可见，违反 §0 设计原则。
