用户点击「1. 扫描全部」或「1. 仅选中面」→ JS 调用 `sketchup.scan_all()` 或 `sketchup.scan_selected()` → Ruby 回调 `do_scan(selection_only:)`

### 4. 创建 Scanner 并执行扫描

文件：`src/scanner.rb`

```ruby
scanner = Scanner.new  # 获取 Sketchup.active_model，初始化 @material_colors = {}
result = scanner.scan(selection_only: false)
```

### 5. Scanner.scan 入口逻辑

```ruby
def scan(selection_only: false)
  items = []
  openings = []
  face_set = Set.new  # 防重：同一面不会被采集两次

  entities =
    if selection_only && !@model.selection.empty?
      @model.selection.to_a   # 仅选中
    else
      @model.entities.to_a    # 整个模型
    end

  entities.each do |entity|
    collect_faces(entity, [], IDENTITY, face_set, items, openings)
  end

  { items: items, openings: openings }
end
```

关键决策：
- 选择为空时**自动降级为全模型扫描**
- `face_set` 跟踪已处理 face.entityID，防止同一个面在不同路径下被重复计入

### 6. collect_faces 递归收集逻辑

```ruby
def collect_faces(entity, path, transform, face_set, items, openings)
  case entity
  when Sketchup::Face        → 6a. 处理面
  when Sketchup::ComponentInstance → 6b. 处理组件实例
  when Sketchup::Group        → 6c. 处理群组
  when Sketchup::Image        → 跳过
  end
end
```

#### 6a. 处理 Sketchup::Face

```
1. 防重检查：if face_set.include?(entity.entityID) → return
2. face_set.add(entity.entityID)
3. 可见性检查：if entity.hidden? || !entity.visible? → return（跳过隐藏面）
4. 获取材质：mat = entity.material || entity.back_material
   - material：正面材质
   - back_material：背面材质
   - 优先取正面，正面为 nil 时取背面
5. 收集材质颜色（用于 UI 色块展示）：
   color = mat.color
   @material_colors[mat_name] = { r:, g:, b:, a: mat.alpha }
6. 面积计算：
   area_m² = face.area(transform) * 0.00064516
   - face.area(transform) 返回 in²（计入累计变换的缩放）
   - × 0.00064516 转换为 m²
7. 世界坐标系法向量：
   world_normal = entity.normal.transform(transform)
   world_normal.normalize!
8. 面中心 Z 坐标（世界空间，米）：
   bb_center_world = entity.bounds.center.transform(transform)
   z_center_m = bb_center_world.z * 0.0254  # inches → meters
9. 透明度判断（门窗洞口识别方式一）：
   if mat&.alpha && mat.alpha < 0.5
     openings << Opening.new(entity.entityID, area_m², [])
     return  ← 该面记为洞口，不加入 items
   end
10. 组装 ScanItem：
    ScanItem.new(
      entity.entityID,           # face_id
      mat_name,                  # su_material（可能为 nil）
      area_m²,                   # area
      [nx, ny, nz],              # normal（世界空间）
      w.round(4),                # width（估算宽度，m）
      h.round(4),                # height（估算高度，m）
      entity.layer.name,         # layer_name
      comp_path,                 # component_path（祖先组件名数组）
      z_center_m.round(4)        # z_center
    )
```

关于 width/height 的估算方式：
```ruby
bb = entity.bounds
scale = [transform.xscale.abs, transform.yscale.abs, transform.zscale.abs].max
dims = [bb.width * scale, bb.height * scale, bb.depth * scale].sort
w = (dims[-2] || 0) * 0.0254  # 次大边
h = (dims[-1] || 0) * 0.0254  # 最大边
```
- 提取 bounding box 三维尺寸，排序后取次大和最大
- 使用 `transform` 三个轴缩放绝对值中的**最大值**作为统一缩放系数
- × 0.0254 英寸转米

#### 6b. 处理 Sketchup::ComponentInstance（组件实例）

```
1. 将组件自身加入路径：
   new_path = path + [entity]
2. 累计变换矩阵：
   new_transform = transform * entity.transformation
3. 递归遍历组件定义内所有子实体：
   entity.definition.entities.each → collect_faces(...)
4. 门窗识别方式二（按名称）：
   if entity.definition.name =~ /(window|door|窗|门)/i
     遍历 definition 内所有面 → 全部记为 Opening
     （注意：这些面的 host_face_ids 为空 []，不关联到宿主墙）
```

**重要**：此处命名匹配仅检查组件定义名称（definition name），而非实例名称。且匹配到的组件内面**同时会被计入 items**（通过步骤 3 的递归），所以这些面会同时出现在 items 和 openings 中。这意味着：
- 门窗组件上的面会被正常扫描
- 同时被标记为 opening（但其 `host_face_ids` 为空，不会扣减任何墙的面积）

#### 6c. 处理 Sketchup::Group（群组）

逻辑与 ComponentInstance 相同，区别在于直接访问 `entity.entities` 而非 `entity.definition.entities`，且**不执行名称匹配**（门窗识别仅针对组件）。

```ruby
new_path = path + [entity]
new_transform = transform * entity.transformation
entity.entities.each { |child| collect_faces(child, new_path, new_transform, ...) }
```

### 7. 合并人工标注面

```ruby
marker_items = Marker.to_scan_items
all_items = result[:items] + marker_items
```

文件：`src/marker.rb`

Marker.to_scan_items 逻辑：
```
1. 遍历模型中所有面（仅顶层 entities，不递归）
2. 检查每个面的属性字典：entity.get_attribute('su_takeoff_marking', 'data')
3. 如果有值，解析 JSON 得到之前标记的数据
4. 构造 ScanItem：
   face_id       = face.entityID
   su_material   = data['su_material_name'] || data['material_name']
   area          = face.area * 0.00064516  ← 注意此处未使用 transform！
   normal        = face.normal（原始法向，未变换）
   width/height  = 0, 0（不估算）
   layer_name    = face.layer.name
   component_path = [data['space'] || '未分组']
   z_center      = face.bounds.center.z * 0.0254
```

**存在的问题**：
- 标注面使用 `face.area` 而非 `face.area(transform)`，对于嵌套在组件/群组内的面，面积可能不准确
- normal 也未经过累计变换
- 标注面的遍历仅在顶层 entities，不递归进入组件/群组，因此**嵌套在深层组件内的已标注面无法被采集**

## 三、审核阶段（Review）

### 9. send_review_state 逻辑

文件：`src/ui/dialog.rb`

```ruby
def send_review_state
  mapping  = PluginState.instance.mapping
  ignored  = PluginState.instance.ignored
  all_items = @last_scan[:items]

  # 1. 收集所有出现过的 SU 材质名
  used_names = all_items.map(&:su_material).compact.uniq

  # 2. 判定每个材质的状态（三态）
  unresolved = used_names.reject { |n| mapping.get(n) || ignored.include?(n) }

  # 3. 构建每种材质的上下文信息（面数、面积、部位分布、空间分布、颜色）
  info = build_material_info(used_names, all_items, @last_scan[:colors])

  # 4. 推送 JSON 到前端
  data = {
    phase: 'review',
    total_materials: used_names.size,
    mapped:    used_names.count { |n| mapping.get(n) },
    ignored:   ignored & used_names,
    unresolved: unresolved,
    materials_info: info,
    categories: PluginState.instance.processes.all_categories
  }
  @dialog.execute_script("window.renderReview(#{JSON.generate(data)})")
end
```

三种材质状态判定：
| 状态 | 条件 | 前端行样式 |
|------|------|-----------|
| 已映射 | `mapping.get(name)` 非 nil | `.row-mapped` 绿色，编辑栏 disabled |
| 已忽略 | `ignored` 数组中存在 | `.row-ignored` 灰色，编辑栏 disabled |
| 待处理 | 以上两者皆不满足 | `.row-unresolved` 黄色，可编辑 |

### 10. build_material_info 上下文构建

```ruby
def build_material_info(names, items, colors)
  # 按材质名分组
  by_name = Hash.new { |h, k| h[k] = [] }
  items.each { |it| by_name[it.su_material] << it if it.su_material }

  names.map do |name|
    group = by_name[name] || []
    parts  = Hash.new(0.0)
    spaces = Hash.new(0.0)

    group.each do |it|
      parts[Calculator.face_orientation(it.normal)] += it.area    # 按部位汇总面积
      spaces[it.component_path.last || '未分组'] += it.area       # 按空间汇总面积
    end

    {
      su_name:    name,
      face_count: group.size,
      total_area: group.sum(&:area).round(2),
      parts:      parts.transform_values { |a| a.round(2) },
      spaces:     spaces.sort_by { |_, a| -a }.first(3)          # 仅取面积最大的 3 个空间
                      .map { |s, a| { name: s, area: a.round(2) } },
      color:      colors[name]
    }
  end
end
```

### 16. Calculator.compute 详细流程

```ruby
def compute(items, openings, process_overrides)
  items = dedup_thin_slabs(items)  # 步骤 17

  # 步骤 18：构建洞口索引
  opening_area_by_face = {}
  openings.each do |op|
    op.host_face_ids.each do |fid|
      opening_area_by_face[fid] ||= 0.0
      opening_area_by_face[fid] += op.area
    end
  end

  # 步骤 19：分组
  groups = Hash.new { |h, k| h[k] = [] }
  items.each do |item|
    next unless @mapping.get(item.su_material)  # 跳过未映射材质
    part   = Calculator.face_orientation(item.normal)
    space  = item.component_path.last || '未分组'
    key    = [space, part, item.su_material]
    groups[key] << item
  end

  # 步骤 20：逐组生成 MaterialUsage
  groups.map do |(space, part, su_mat), grp_items|
    record  = @mapping.get(su_mat)
    net_area = grp_items.sum { |it|
      deduction = opening_area_by_face[it.face_id] || 0.0
      [it.area - deduction, 0.0].max       # 保证不为负
    }

    waste_rate = if process_overrides[su_mat]
      # 工艺覆盖仅取第一个匹配的 ProcessDef
      proc_def = @processes.processes_for(record.category)
                    .find { |p| p.name == process_overrides[su_mat] }
      proc_def&.waste_rate || record.default_waste_rate
    else
      record.default_waste_rate
    end

    MaterialUsage.new(
      space: space, part: part,
      material_name: record.material_name,
      category: record.category,
      spec: record.spec,
      net_area: net_area.round(4),
      waste_rate: waste_rate,
      su_material_name: su_mat
    )
  end
end
```

当前代码中 `process_overrides` 始终为 `{}`，因此实际只使用材料的 `default_waste_rate`。

### 17. 薄板去重（dedup_thin_slabs）

**问题**：楼板/天花作为薄体建模时，上下两面是同一种材质，naive 扫描会把两面都计入，导致面积翻倍。

**算法**：
```
1. 按空间分组计算每个空间的 Z 中位数：
   space_z_mid[space] = (所有面的 z_center 的最小值 + 最大值) / 2

2. 按 (空间, 材质) 分组

3. 每组内找匹配对：
   - up：normal.z > 0.866（朝上的面）
   - down：normal.z < -0.866（朝下的面）
   - 匹配条件（三个同时满足）：
     a. 面积差 ≤ 2%（SLAB_AREA_TOLERANCE = 0.02）
     b. Z 中心差 ≤ 15cm（SLAB_Z_TOLERANCE_M = 0.15）
     c. down 面未被之前的 up 面匹配（一个朝下面只能匹配一个朝上面）
   - 判定 slab 位置然后决定删除哪一面：
     slab_z = (up.z_center + down.z_center) / 2
     if slab_z ≤ space_z_mid → 删除朝下面（保留地面可见面）
     if slab_z > space_z_mid  → 删除朝上面（保留天花可见面）

4. 从 items 中移除被标记删除的面
```

**前提条件**：
- 仅匹配同一材质的面
- 同一朝下面最多被匹配一次
- 空间内必须有足够的面来计算 Z 中位数

### 18. 构建洞口扣减映射

```ruby
opening_area_by_face = {}    # { face_id → 累计扣减面积 }
openings.each do |op|
  op.host_face_ids.each do |fid|
    opening_area_by_face[fid] += op.area
  end
end
```

**当前行为**：
- Scanner 产生的 Opening，其 `host_face_ids` **始终为空数组 `[]`**（见步骤 6a、6b）
- 因此 `opening_area_by_face` **始终为空哈希**，扣减逻辑实际不生效
- 测试用例（test_calculator.rb test_deduct_openings）手动构造了带 `host_face_ids` 的 Opening 来验证扣减逻辑正确性

**这意味着**：透明面（alpha < 0.5）和门窗组件面仅从 items 中排除，并不作为"扣减"应用于相邻墙面。

### 19. 分组逻辑

```ruby
groups = Hash.new { |h, k| h[k] = [] }
items.each do |item|
  next unless @mapping.get(item.su_material)  # ← 未映射的材质被静默排除
  part  = Calculator.face_orientation(item.normal)
  space = item.component_path.last || '未分组'
  key   = [space, part, item.su_material]
  groups[key] << item
end
```

- **分组键** = `[空间名, 部位(floor/wall/ceiling), SU材质名]`
- 空间名取 `component_path` 的最后一级（即最近祖先组件名）
- 未赋材质（su_material 为 nil）的面在 `face_orientation` 之前就被 `next unless @mapping.get(nil)` 过滤掉

### 20. 面朝向判定

```ruby
def self.face_orientation(normal)
  z = normal[2].abs
  if z > 0.866           # cos(30°) ≈ 0.866，即法向量与 Z 轴夹角 < 30°
    normal[2] > 0 ? 'floor' : 'ceiling'
  else
    'wall'
  end
end
```

| 法向量 Z 分量 | 判定 |
|-------------|------|
| Z > 0.866 | 地面（floor） |
| Z < -0.866 | 天花（ceiling） |
| \|Z\| ≤ 0.866 | 墙面（wall） |

### 21. 损耗率确定

```
优先级：
1. process_overrides 中指定了工艺名 → 从 ProcessLibrary 查找该工艺的 waste_rate
   找不到 → 回退到 mapping 的 default_waste_rate
2. 无覆盖 → 直接使用 mapping 的 default_waste_rate
```

当前 `process_overrides` 恒为 `{}`，所以始终走路径 2。

### 22. 按材料汇总（group_by_material）

```ruby
def group_by_material(usages)
  grouped = Hash.new { |h, k| h[k] = { net_area: 0.0, purchase_qty: 0.0, items: [] } }
  usages.each do |u|
    grouped[u.material_name][:net_area]    += u.net_area
    grouped[u.material_name][:purchase_qty] += u.purchase_qty
    grouped[u.material_name][:items]        << u
  end
  # 四舍五入到 2 位小数
  grouped.each_value { |v| v[:net_area] = v[:net_area].round(2); v[:purchase_qty] = v[:purchase_qty].round(2) }
  grouped
end
```

汇总维度：**跨空间、跨部位**，按真实材料名合并。

### 23. 推送结果到前端

```ruby
data = {
  phase: 'done',
  by_space:    usages.map(&:to_h),      # 供「按空间」和「明细」视图
  by_material: by_material.transform_values { |v|
    { net_area: v[:net_area], purchase_qty: v[:purchase_qty] }
  }
}
@dialog.execute_script("window.renderResults(#{JSON.generate(data)})")
```

前端三种视图切换：
- **按空间汇总（by-space）**：空间 / 部位 / 材料 / 净面积 / 损耗率 / 采购量 / 规格
- **按材料汇总（by-material）**：材料 / 净面积 / 采购量
- **展开明细（detail）**：空间 / 部位 / 材料 / 面积 / SU 材质名（逐行展开，等同 by_space 去掉损耗和采购量列，增加 SU 材质名列）

## 六、已知问题与待确认点

1. **洞口扣减不生效**：Scanner 产生的 Opening 均带空 `host_face_ids`，使得 Calculator 中的扣减逻辑（步骤 18）实际不执行。门窗被排除但不从相邻墙扣除。

2. **标注面面积计算不准确**：Marker.to_scan_items 使用 `face.area`（英寸²）直接×0.00064516，未传入 transform。若标记面在组件/群组内，缩放不会被计入。

3. **标注面 normal 未变换**：如果标记面位于旋转过的组件内，其法向量是世界变换前的值，会导致部位判定错误。

4. **标注面采集不递归**：Marker.all_marked_faces 仅遍历 `model.entities` 顶层，嵌套在组件/群组内的已标注面被遗漏。

5. **薄板去重使用统一缩放**：Scanner 中 width/height 的 scale 取三个轴缩放的 max，对非均匀缩放（如压扁的板）不够精确。

6. **空间识别依赖组件名**：`component_path.last` 作为空间名。无父组件的面归类为"未分组"。不能识别更复杂的空间嵌套（如"一楼 > 客厅"）。

7. **门窗面同时存在于 items 和 openings**：组件名匹配产生的 Opening 对应的面仍被正常计入 items，会在统计中出现门窗上的材质。

8. **group_by_material 的两重汇总精度不一致**：`compute` 中 `net_area.round(4)`，`group_by_material` 中 `round(2)`。
